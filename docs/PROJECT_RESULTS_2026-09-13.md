# StateKV 项目成果汇总

截至 2026 年 9 月 13 日。实验已按要求暂停，本文汇总已有成果，不启动新实验，也不改动原始结果。

## 1. 项目结论

StateKV 的研究主线是：缓存压缩的影响依赖模型当前状态，而当前不重要的证据，可能在后续查询中成为关键。项目由精确的状态相关评价，逐步转向当前查询路由，再形成基于目标模型未来生成的 Cheap-R2。

目前最有力的任务结果是紧预算的多键检索。Cheap-R2 在完整前缀上做一次 H=32 的因果 rollout，再执行严格淘汰，能保留当前查询尚未激活的证据。它并非所有任务上的通用最优策略：多查询任务常与更便宜的策略打平，历史 QA 没有稳定优势，答案得分与轨迹 KL 也并不总是一致。

历史 MLX/4-bit 实验与最新 CUDA/BF16 实验分开报告。两者的模型、精度、提示词和任务配置不同，不能据其绝对分数计算跨版本提升。

## 3. 历史 Cheap-R2 benchmark

Qwen3-8B-4bit，MLX，严格淘汰、无冷恢复，64 个解码周期。多键检索 50 个新样本，QA 与 GovReport 各 20 个样本。以下为项目已有记录，非本次 CUDA 结果。

| 任务 / 预算 | FULL | Current-QK | SnapKV | H2O | LAQ | LAQ++ | Cheap-R2 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Multikey / 128 | 82.0 | 1.0 | 0.5 | 0.0 | 0.0 | 0.0 | 48.5 |
| Multikey / 256 | 82.0 | 21.0 | 0.0 | 5.0 | 29.5 | 21.0 | 70.0 |
| Multikey / 512 | 82.0 | 25.5 | 55.0 | 16.0 | 84.5 | 68.5 | 81.0 |
| HotpotQA / 256 | 40.0 | 35.0 | 35.0 | 35.0 | 30.0 | 25.0 | 35.0 |
| 2WikiMQA / 256 | 45.0 | 55.0 | 50.0 | 45.0 | 45.0 | 40.0 | 45.0 |
| GovReport / 256 | 6.25 | 6.49 | 6.09 | 6.23 | 6.24 | 6.01 | 6.03 |

多键检索预算 256 时，Cheap-R2 比 QK 高 49 个百分点，配对 95% CI 为 [39.0, 58.5]；比 LAQ 高 40.5 个百分点，CI 为 [29.5, 51.0]。预算 512 时，Cheap-R2 对 LAQ 的差值为 -3.5，CI [-11.5, 4.0]，没有明确优胜。

成本：multikey@256 的 Cheap-R2 平均 75.5 秒/序列，QK 为 53.4 秒。减少 refresh 的实验表明一次 query-onset 选择保留了主要收益；起始后当前/未来 top-budget 集合重合度约 0.996。

QA 的原始 substring 得分会受到解释段和答案别名影响。已有答案级复核中，HotpotQA 的 QK/R2 均为 40，2WikiMQA 为 40/45；20 个样本不足以支持稳定的 QA 优势。GovReport 的 64-token 输出主要是开头片段，表中 ROUGE-L 不作为完整摘要质量结论。

来源：[Cheap-R2 报告](experiments/07_cheap_r2.md)、[benchmark 报告](experiments/08_benchmark_results.md)，原始结果位于 `results/statekv_counterfactual/`。

### 4.3 KL 与答案得分的区别

CUDA 轨迹 KL 在同一条策略生成前缀上对完整缓存 replay，衡量输出分布偏离程度，越低越好；它不等于正确答案率。

| 配对设置 / 预算 256 | R2 得分 / KL | 对照得分 / KL | 观察 |
|---|---|---|---|
| 1.7B / 8K / 四键 | 100 / 0.799 | LAQ 41.50 / 1.619 | R2 两项均更好 |
| 4B / 16K / 四键 | 100 / 1.359 | LAQ 14 / 0.931 | R2 答案更好，KL 更高 |
| 4B / 8K / 八键 | 61.25 / 1.252 | LAQ++ 0.75 / 0.940 | 较低 KL 不保证检索正确 |
| 4B / 8K / 多查询 | 100 / 0.879 | QK 100 / 0.145 | 答案打平，QK 分布更接近 FULL |
| 1.7B / 16K / 变量 | 68 / 1.790 | QK 54 / 1.555 | 任务收益与分布偏离同时存在 |

CUDA 中的策略是项目实现，分数对应本项目的严格预算、sink/recent 保留、层与头聚合配置，不等于原论文或官方 leaderboard 数字。各策略全部预算的得分、KL、执行时间和缓存峰值已保存在本地 `summary.json`、`metrics.csv` 与逐评测 JSON 中。

## 5. 最新成果的解释

1. 四键检索优势在 CUDA 的 1.7B、4B 与 4K–16K 设置中延续：R2 在预算 256 的完整设置达到 97–100 分，而现有其他压缩策略明显更低。
2. 八键检索对预算敏感。4B 在 4K/8K 的预算 256 只有 59.25/61.25，预算 512 升至 99.25/100；128 预算通常只能恢复约一半请求值。不能用四键满分替代八键表现。
3. 更大模型并不在所有压缩条件下更好：1.7B 的八键@256 得分高于 4B，说明需要同时考虑模型注意力结构、预算与选择规则。
4. 变量追踪也有任务收益，但 FULL 本身随长度和模型变化，不能把它与多键检索合并成单一准确率。
5. 多查询中 R2 经常打平 QK、SnapKV 或 LAQ，并且 KL 可能更高，没有一致优势。
6. 历史 8B 支持检索特定的收益；最新 CUDA 结果扩大了合成任务与长度覆盖，但尚未验证 CUDA 8B、官方 LongBench、额外 seeds 或 horizon 消融。
