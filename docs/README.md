# StateKV documentation index

All project documentation lives under this directory. The root
[`README.md`](../README.md) is the only entry point outside `docs/`.

## Reading order

If you are new to the project, read in this order:

1. [`RESEARCH_HISTORY.md`](RESEARCH_HISTORY.md) — what was tried, phase by
   phase; distinguishes "believed at the time" from "known now".
2. [`FINDINGS.md`](FINDINGS.md) — what still stands, graded by evidence
   strength (strong / conditional / observations / negative / open).
3. [`FAILURE_ANALYSIS.md`](FAILURE_ANALYSIS.md) — why the original main line
   failed, with each explanation graded SUPPORTED / PLAUSIBLE / SPECULATION.
4. [`NEXT_RESEARCH_DIRECTIONS.md`](NEXT_RESEARCH_DIRECTIONS.md) — the
   empirical gaps worth building on next.

## Reference documents

- [`EXPERIMENT_REGISTRY.md`](EXPERIMENT_REGISTRY.md) — every experiment:
  question, substrate, config, script, raw result, status
  (VALID / NEGATIVE / SUPERSEDED / INVALIDATED / …).
- [`REPRODUCIBILITY.md`](REPRODUCIBILITY.md) — finding → config → script →
  raw-result chain audit.
- [`CODE_AUDIT.md`](CODE_AUDIT.md) — module classification (core / legacy /
  dead), defensive-code risks, duplicate implementations.

## Subdirectories

- [`evidence/`](evidence/) — raw experiment record: preregistered protocols,
  search logs, closure reports, gate verdicts. These are historical
  documents; they are kept as written (paths updated only when files moved).
  - [`evidence/tables/`](evidence/tables/) — human-readable verdict summaries
    generated by the builders in `analysis/tables/*.py` (the CSV/parquet
    siblings stay in `analysis/tables/`).
- [`proposals/`](proposals/) — architecture/design notes.
- [`archive/`](archive/) — superseded material kept for traceability (e.g.
  the retest run queues).

## Deliberately not here

- `results/**/report.md` — generated per-run reports, kept next to their raw
  data so the finding → raw-result chain stays intact. The runners
  regenerate them in place.
- `analysis/tables/*.csv|parquet|json` — machine-readable derived tables.

This policy is enforced by `tests/test_repository_architecture.py`.
