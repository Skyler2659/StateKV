## 1. Project Overview

### 1.1 Problem Statement

Large Language Models (LLMs) in streaming applications (multi-round dialogue, long-document
processing) face two key challenges:

1. **Memory**: KV cache grows linearly with sequence length, consuming extensive GPU memory.
2. **Generalization**: Models trained with finite context windows (e.g., 4096 tokens) cannot
   natively handle longer sequences.

The original StreamingLLM (Xiao et al., 2023) observed that keeping the KV of **initial tokens**
("attention sinks") largely recovers window attention performance. However, its token selection
is purely heuristic: keep the first `k` tokens + the most recent `m` tokens, discard everything in
between. This ignores the *semantic importance* of individual tokens.

### 1.2 Our Approach

We introduce **L1-Robust KV Cache**, which replaces the heuristic "first-k + last-m" strategy
with a mathematically principled token selection mechanism based on **ℓ₁ leverage scores**
computed via **CountSketch**-based ℓ₁ subspace embeddings.

**Core insight**: The KV cache eviction problem can be reformulated as a *subspace embedding*
problem. Given a budget of `B` tokens, we want to select the `B` rows of the Value matrix `V`
whose linear combinations best approximate the full attention output in the ℓ₁ norm.

### 1.3 Relationship to Baselines

| Method | Selection Criterion | Theoretical Foundation |
|--------|-------------------|----------------------|
| StreamingLLM (orig) | Position (first-k + last-m) | Heuristic (attention sink observation) |
| H2O | Cumulative attention score | Empirical |
| SnapKV | Attention pattern matching | Empirical |
| CurDKV | CUR decomposition (≈ ℓ₂) | ℓ₂ matrix approximation |
| **L1-Robust (ours)** | **ℓ₁ leverage scores** | **ℓ₁ subspace embedding (Woodruff 2014)** |

Our method is the **only one** that uses ℓ₁ geometry and sketching theory for KV cache eviction.

## 2. Mathematical Foundations

### 2.1 The KV Cache as a Matrix

Consider a single attention head at a single layer. After processing $n$ tokens, the Value
states form a matrix:

$$V \in \mathbb{R}^{n \times d}$$

where $d = \text{head\_dim}$ (typically 64–128), $n = \text{sequence\_length}$, and each row
$V_{i,*} \in \mathbb{R}^d$ is the value vector of token $i$.

The attention output for a query $q$ is:

$$\text{output}(q) = \sum_{i=1}^{n} \alpha_i \cdot V_{i,*}$$

where $\alpha_i = \text{softmax}(q \cdot K^T / \sqrt{d})_i$ are the attention weights.

### 2.2 Subspace Embedding Formulation

Given a budget $B \ll n$, we must select $B$ rows of $V$ (indices $S \subset [n]$, $|S| = B$) such
that for any query $q$, the approximated output:

$$\text{output}_S(q) = \sum_{i \in S} \alpha_i \cdot V_{i,*} \;/\; p_i$$

is close to $\text{output}(q)$, where $p_i$ is the selection probability (importance sampling weight).

The **ℓ₁ subspace embedding** approach (Woodruff, 2014, §3.4–3.5) says: we can select rows
based on their **ℓ₁ leverage scores** to preserve the ℓ₁ geometry of $V$'s column space.

### 2.3 ℓ₁ Leverage Scores

**Definition** (ℓ₁ leverage score). For a matrix $V \in \mathbb{R}^{n \times d}$, let
$V = U \cdot R$ be a well-conditioned basis decomposition (where $R$ is obtained from QR of
an ℓ₁ subspace embedding of $V$). The ℓ₁ leverage score of row $i$ is:

$$\ell^{(1)}_i = \|U_{i,*}\|_1 = \|(V \cdot R^{-1})_{i,*}\|_1$$

High-leverage rows are those that cannot be well-approximated by linear combinations of
other rows in the ℓ₁ norm. These are the "structurally important" tokens.

### 2.4 ℓ₁ Subspace Embedding (Construction B, Woodruff §3.5)

The embedding $S: \mathbb{R}^n \to \mathbb{R}^r$ (with $r = O(d^2)$) is constructed as:

$$S = \Phi \cdot D$$

where:
- $\Phi$: CountSketch matrix ($r \times n$), each column has exactly one non-zero entry (±1)
  randomly placed
- $D$: diagonal matrix ($n \times n$), $D_{i,i} = 1/E_i$ where $E_i \sim \text{Exp}(1)$ i.i.d.

**Key property** (Woodruff Theorem 38): $S$ is an ℓ₁ subspace embedding, meaning for all
$x \in \mathbb{R}^d$:

$$(1-\varepsilon)\|Vx\|_1 \leq \|SVx\|_1 \leq (1+\varepsilon)\|Vx\|_1$$

with $r = O(d^2/\varepsilon^2)$ rows — independent of $n$.

The exponential weights $1/E_i$ are crucial: they convert the ℓ₂ embedding property of
CountSketch into an ℓ₁ embedding. Without them, CountSketch only preserves ℓ₂ norms.

### 2.5 Computing ℓ₁ Leverage Scores Efficiently

The pipeline:

```
Step 1: S·V = Φ · diag(1/E) · V        [Cost: O(nd·log n) via sparse CountSketch]
Step 2: QR(S·V) → R ∈ ℝ^{d×d}           [Cost: O(rd²), very small since r = O(d²)]
Step 3: R^{-1}                           [Cost: O(d³), trivial for d ≤ 128]
Step 4: ℓ̂ᵢ = ‖(V·R^{-1})_{i,*}‖₁        [Cost: O(nd²) or O(nd) with caching]
```

**Critical implementation choice**: Instead of using random projection (which would require
Cauchy-distributed entries for correctness), we compute the exact ℓ₁ leverage scores via
$V \cdot R^{-1}$. This is:
- Mathematically **exact** (no approximation error in the score estimation step)
- Computationally **cheap** for typical $\text{head\_dim}$ ($d \leq 128$):
  $O(n d^2) = O(129 \times 16384) \approx 2\text{M}$ FLOPs per recompute
- Only recomputed every $\text{recompute\_interval}$ steps (default: 32)

### 2.6 Token Selection via ℓ₁ Scores

Given scores `s ∈ ℝⁿ` (one per token), we select `B` tokens using a mixed budget strategy:

```
selection = {
    sink_tokens:          positions [0, k)        (attention sinks)
    recent_tokens:        positions [n-1-m, n-1)  (recency block)
    ℓ₁-selected_tokens:   top-p scores from remaining history
    last_token:           position [n-1]           (always kept)
}

budget = k + m + p + 1 = B
```

When `m = 0`, this reduces to the original L1-only strategy.
When `m = B - k - 1`, this reduces to the StreamingLLM heuristic (but we keep `p > 0`).

### 2.7 Why ℓ₁ Instead of ℓ₂?

| Property | ℓ₂ leverage scores | ℓ₁ leverage scores |
|----------|-------------------|-------------------|
| Sensitivity to outliers | Quadratic (‖U_{i,*}‖₂²) | Linear (‖U_{i,*}‖₁) |
| Dominance by few tokens | Yes (one token can dominate) | No (more balanced) |
| Robustness to noise | Low | **High** |
| Attention context | Outliers absorb most attention | Attention is more distributed |

In transformer attention, "outlier tokens" naturally exist (attention sinks, massive
activations). ℓ₂ would give these tokens disproportionately high scores, crowding out
moderately-important tokens. ℓ₁'s linear scaling preserves diversity in the selected set.

## 4. Algorithm Design

### 4.1 L1RobustKVCache: Complete Algorithm

```
Algorithm: L1-Robust KV Cache Eviction

Input: past_key_values = [(K₀,V₀), ..., (K_L,V_L)], each K_l,V_l ∈ ℝ^{B×H×S×D}
       cache_size B, num_sink_tokens k, recent_keep m
       sketch_dim r, recompute_interval T
Parameters: per_layer (bool), use_reweight (bool)

Initialize:
  _estimators = {}      # Per-layer L1LeverageScoreEstimator
  _steps = 0            # Global step counter
  _fallback_cache = StartRecentKVCache(k, B-k)  # Fallback for unsupported shapes

Procedure __call__(past_key_values):
  If past_key_values is None: return None
  If cache is DynamicCache type: warn, return unchanged
  If seq_dim ≠ 2: warn, delegate to _fallback_cache

  _steps += 1
  shared_keep = None

  For each layer l ∈ [0, L]:
    If per_layer:
      (keep, rw) = _select_indices_for_layer(l, V_l)
    Else:
      If shared_keep is None:
        (shared_keep, rw) = _select_indices_for_layer(0, V₀)
      keep = shared_keep

    If keep is None:  # seq_len ≤ cache_size
      items.append((K_l, V_l))     # No eviction needed
    Else:
      K'_l = index_select(K_l, seq_dim, keep)
      V'_l = index_select(V_l, seq_dim, keep)
      If rw is not None: V'_l *= rw  # Importance sampling reweight
      items.append((K'_l, V'_l))

  Return preserve_type(past_key_values, items)

Procedure _select_indices_for_layer(l, V_l):
  v_rows = V_l[0].mean(dim=0)          # [S, D], avg over heads
  If v_rows is None or seq_len ≤ B: return None
  estimator = _get_or_create_estimator(l, head_dim)
  force_refit = (_steps % T == 0)
  scores = estimator.scores(v_rows, force_refit)
  keep = _select_with_recency_mix(scores)
  rw = compute_reweight(scores, keep) if use_reweight else None
  return (keep, rw)

Procedure _select_with_recency_mix(scores):
  seq_len = len(scores)
  budget = cache_size
  If seq_len ≤ budget: return all indices

  sink = min(k, budget)
  max_recent = budget - sink - 1
  recent = min(m, max_recent)
  l1_budget = budget - sink - recent - 1

  keep = []
  keep.append([0, 1, ..., sink-1])            # Attention sinks
  If recent > 0:
    keep.append([seq_len-1-recent, ..., seq_len-2])  # Recent block
  If l1_budget > 0:
    candidate_scores = scores[sink : seq_len-1-recent]
    top_l1 = topk(candidate_scores, l1_budget)       # ℓ₁ selected
    keep.append(top_l1.indices + sink)
  keep.append([seq_len - 1])                   # Last token (always)

  keep = unique(sorted(keep))
  If len(keep) > budget: keep = keep[-budget:]  # Truncation safeguard
  return keep
```

### 4.2 Complexity Analysis

For a single eviction step with sequence length `S`, head dimension `d`, cache budget `B`,
sketch dimension `r`, and `L` layers:

| Operation | Cost (per layer) | Total (L layers) |
|-----------|-----------------|------------------|
| V extraction + head averaging | O(S·d) | O(L·S·d) |
| CountSketch (`Φ·D·V`) | O(S·d) | O(L·S·d) |
| QR decomposition | O(r·d²) | O(L·r·d²) |
| R^{-1} | O(d³) | O(L·d³) |
| Score computation (`V·R^{-1}`) | O(S·d²) | O(L·S·d²) |
| Top-k selection | O(S·log S) | O(L·S·log S) |
| Index selection | O(B·d) | O(L·B·d) |

**Amortized analysis**: The expensive operations (QR, R^{-1}) are performed only once every
`T` steps (default: 32). Between refits, only score computation and selection are needed.
Score computation between refits is `O(S·d²)` per layer — for pythia-410m (d=64, S≈128),
this is ~0.5M FLOPs per layer, negligible compared to the transformer forward pass.

**Memory overhead**: Per layer:
- CountSketch buckets + signs: `2·S·4` bytes ≈ 1KB
- `R^{-1}`: `d²·4` bytes ≈ 16KB (float32, d=64)
- Total: ~17KB per layer × 24 layers ≈ 400KB

```

plain               1536     1.1025      10.13         1536

```

**Interpretation**: On repeat text, `main` (StreamingLLM) nearly matches `plain` because the

artifact of the benchmark — not reflective of real performance.

ℓ₁-only (`sketching`, PPL=2.27) outperforms sliding_window (PPL=2.43), showing ℓ₁ captures
useful structural information even when the content is repetitive.

### 6.3 Mixed Budget Grid Search

```
=== Grid Search: recent_keep vs PPL (wikitext, cache_size=128) ===
mixed_recent_keep     ppl      tok/s
                32   24.31      12.82
```

**Interpretation**: The mixed budget reaches PPL=22.21, essentially matching `main`'s 22.01.
This means ℓ₁-selected tokens from distant history provide comparable information to
simply keeping more recent tokens — but with better long-range retrieval (see needle tests).
The optimal `recent_keep=80` gives ℓ₁ a budget of 43 tokens for distant-history selection.

The curve is not strictly monotonic (96 has slightly higher PPL than 80), suggesting the
ℓ₁ budget has non-zero value — squeezing it below 43 tokens degrades performance.

retain structurally distinct tokens from long-ago contexts.

leverage scores are NOT just detecting out-of-vocabulary anomalies — they genuinely identify
structurally important tokens even when the surface-level statistics are uniform.

## 8. Key Findings and Interpretations

### 8.1 Finding 1: ℓ₁ Alone Is Not Enough

Pure ℓ₁ scoring (no recency budget) performs *worse* than plain recency on standard PPL
(ll_only PPL=61.8 vs sliding_window PPL=52.9 on wikitext). This is because:

- Language modeling has a strong **recency bias**: the most recent tokens are
  disproportionately informative for predicting the next token.
- ℓ₁ leverage scores measure *structural importance in V's column space*, which does
  not correlate perfectly with *predictive importance* for the next token.

### 8.2 Finding 2: ℓ₁ + Recency Is Synergistic

Mixed budget (l1_mixed) achieves PPL=22.21, matching StreamingLLM's 22.01, while providing
dramatically better long-range retrieval (15-250× on needle tests). This synergy arises
because:

- **Recency** handles the short-range prediction (local context).
- **ℓ₁** handles the long-range retrieval (structural key tokens from distant history).
- Together they cover both bases: local fluency + long-range memory.

### 8.3 Finding 3: ℓ₁ Excels at Long-Range Retrieval

Needle test results (15-250× over baselines) show that ℓ₁ leverage scores are extremely
effective at identifying and preserving "needle" tokens from distant contexts. This is the
**unique selling point** of the method — other KV cache compression methods (H2O, SnapKV,
StreamingLLM) cannot do this because they are fundamentally recency-biased.

### 8.4 Finding 4: ℓ₁ ≠ Simple Anomaly Detection

The invisible needle test proves ℓ₁ leverage scores capture genuine structural importance
rather than merely detecting unusual tokens. The needle text uses the same vocabulary as
the haystack, yet ℓ₁ still identifies and preserves it with high fidelity.

### 8.5 Finding 5: Position Shift Is Critical

Early experiments (before fixing pos_shift) showed sketching PPL=399 — completely broken.
After enabling pos_shift (GPT-NeoX attention forward modification), PPL dropped to 2-3 on
needle tests. Without position shift correction, the scattered token positions after eviction
produce wildly incorrect RoPE encodings, destroying model performance.

## 10. Current Limitations

### 10.1 Model Scale

All experiments use pythia-410m-deduped (400M parameters). Larger models (1B, 3B, 7B) have:
- Higher-dimensional V spaces (head_dim 128 instead of 64) → richer ℓ₁ structure
- More layers → higher computational cost for per-layer selection
- Better inherent long-range modeling ability → ℓ₁ benefit may change

### 10.2 Benchmark Coverage

Current benchmarks are custom-built (wikitext PPL + synthetic needle tests). Missing:
- **LongBench**: 16 standard long-context tasks
- **RULER**: Multi-needle retrieval (1-64 needles)
- **InfiniteBench**: 100K+ token reasoning
- **HumanEval/MT-Bench**: Generative quality evaluation

### 10.3 Baseline Methods

Currently compared against:
- StreamingLLM (original heuristic)
- Sliding window (pure recency)
- Plain (no eviction)

Missing baselines (required for publication):
- **H2O** (NeurIPS 2023, attention-based)
- **SnapKV** (2024, attention pattern matching)
- **Quest** (2024, query-aware importance)

### 10.4 Speed Benchmarking

All speed measurements are on CPU with a 400M model. GPU speed measurements on practical
models (1B-7B) are needed to evaluate real-world overhead.

### 10.5 Implementation

- `random_cols` parameter is dead code throughout the stack
- `l1_weighted_sampling` function is superseded by `_select_with_recency_mix` but not removed
- Warning spam: `L1LeverageScoreEstimator.__init__` prints per-layer warnings
- No seed management for reproducible experiments
- CountSketch hash functions are randomly regenerated on each refit (non-incremental)
